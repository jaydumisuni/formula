# RS-BOOTSTRAP-SEED — P12 Targeted Bootstrap Strategy Spike

**Status:** COMPLETE — strategy selected for P12 implementation

This spike is mandatory roadmap work. It compares preserved donor patterns against the actual post-P11 implementation before any P12 bootstrap code is written.

## Actual post-P11 substrate

P12 begins from exact finally frozen P11 proof authority:

```text
P11 frozen proof head: 6f8ce7bb6702ea1baf119aab9950aa5ba0f87283
P11 canonical run/job: 34031806639 / 101482593250
P11 result:            success
```

The implementation is currently a Rust 1.98.0 workspace with checker authority centered in `formula-check`, immutable structural identities in `formula-core`, execution separated from checking, and read-only canonical CI. The smallest existing authority-critical checker is `formula-check::identity`: it accepts an artifact only when independently recomputed `StructuralIdentity::structural_digest()` equals the expected digest.

A full Rust compiler self-host is disproportionate to P12's trust-reduction gate. The roadmap requires a selected authority-critical component to be rebuilt by a self-host path and admitted only after an independent validator checks the successor. It does not require Formula to replace rustc in one phase.

## Donor comparison

### CakeML — verified semantic compiler + self bootstrap

Official source: https://cakeml.org/

Useful donor pattern:

- compiler semantics are formalized;
- compiler output has a machine-checked semantic-correctness story;
- the compiler can compile itself;
- the self-compiled binary is not treated as authoritative merely because self-compilation succeeded.

Fit for Formula:

- adopt the **semantic-equivalence-first** idea;
- express a tiny authority-critical checker in a Formula-owned Bootstrap Core;
- rebuild that checker through the Bootstrap Core compiler;
- require an independent validator to establish successor equivalence.

Rejected for P12:

- importing HOL/CakeML or attempting a full verified Rust compiler. That would dominate the phase and widen the trusted stack rather than reduce it pragmatically.

### Mes / stage0 — explicit minimal seed and staged trust reduction

Official sources:

- https://www.bootstrappable.org/projects/mes.html
- https://www.gnu.org/software/mes/manual/html_node/Bootstrappable-Builds.html

Useful donor pattern:

- make binary seeds explicit rather than implicit;
- record provenance of every seed;
- build through small auditable stages;
- shrink trust gradually instead of claiming a seed-free system prematurely.

Fit for Formula:

- treat the pinned Rust 1.98.0 toolchain as **B0 explicit external seed**, not as invisible ambient authority;
- record exact toolchain version, compiler commit, host, executable hashes and reproducible setup instructions in `BootstrapSeedManifest`;
- establish Stage0/Stage1/Stage2 bootstrap generations explicitly.

Rejected for P12:

- reproducing Mes/stage0's machine-level bootstrap ladder. Formula already has a conventional reproducible Rust seed, and P12's goal is trust reduction of Formula authority components, not constructing a new operating-system toolchain.

### Verified compilation / CompCert — semantic preservation across compilation

Official source: https://compcert.org/

Useful donor pattern:

- compiler correctness is a statement about preservation of source semantics into generated artifact behavior;
- successful compilation is not itself evidence of semantic correctness.

Fit for Formula:

- define Bootstrap Core source semantics independently of its generated bytecode encoding;
- validate the selected checker successor against source semantics, not only file bytes;
- record normalization/equivalence level explicitly in each rebuild manifest.

Rejected for P12:

- importing CompCert itself. Its public release also carries licensing constraints inappropriate as a Formula runtime dependency; P12 only borrows the semantic-preservation pattern.

### Diverse Double-Compiling — trusting-trust resistance

Official source: https://dwheeler.com/trusting-trust/dissertation/

Useful donor pattern:

- a self-reproducing compiler is insufficient to establish trust;
- generation and validation must be genuinely distinct;
- diverse recompilation can expose a compiler binary that does not correspond to its claimed source.

Fit for Formula:

- enforce `generator_identity != validator_identity` structurally;
- implement two independent code paths:
  1. Formula Bootstrap Core generator/rebuilder;
  2. checker-owned reference validator/recompiler;
- compare normalized successor artifacts and independently evaluate checker behavior;
- fail closed on any unexpected difference.

## Selected P12 seed/toolchain strategy

### B0 — explicit external seed

Use the already frozen conventional toolchain as an explicit, published seed:

```text
Rust: 1.98.0
rustc commit: 88d9e12ae178fab0fb5cc050a94da85685d449ea
cargo: 1.98.0 (797e8a9bc 2026-08-05)
canonical host: x86_64-unknown-linux-gnu
```

The P12 canonical workflow must additionally hash the actual `rustc` and `cargo` executables and bind those hashes into `BootstrapSeedManifest` rather than trusting version strings alone.

B0 builds the initial Bootstrap Core generator and the independent bootstrap validator. B0 is **seed provenance**, not self-host authority.

### B1 — minimal authority loader/checker

Target the semantic law behind `formula-check::identity` as the first authority-critical self-hosted component:

```text
input:  canonical artifact structural digest
input:  expected digest
output: VALID iff actual == expected
output: REJECT otherwise
```

The Bootstrap Core representation must be small enough for two independent implementations to parse/evaluate exhaustively.

### B2 — Formula Bootstrap Core

Introduce a tiny deterministic typed instruction set sufficient for the identity checker and its bootstrap compiler path. Initial instruction family should remain intentionally minimal, e.g.:

```text
LOAD_ACTUAL_DIGEST
LOAD_EXPECTED_DIGEST
DIGEST_EQ
RETURN_VALID
RETURN_REJECT
```

The exact instruction set is frozen by the P12 design, not by this research note.

Required properties:

- canonical source representation;
- canonical bytecode representation;
- structural identities for source, bytecode, generator and validator;
- no network/model calls;
- deterministic evaluation;
- no authority mutation API.

### B3 — self-host path

Create a Formula-owned Bootstrap Core compiler/rebuilder that translates canonical Bootstrap Core source into canonical bytecode.

The selected identity checker is rebuilt through this path. The generated successor is only a **candidate bootstrap artifact**.

### B4 — independent/diverse validation path

Implement a checker-owned reference translator/evaluator that does not call the generator implementation.

It must independently:

1. parse canonical Bootstrap Core source;
2. generate/normalize the expected bytecode using separate code;
3. compare candidate successor against the independent result;
4. execute both source semantics and successor bytecode over the bounded complete identity-checker truth table;
5. issue bootstrap validation evidence only if all equivalence obligations pass.

Structural law:

```text
generator_identity != validator_identity
```

### B5 — recursive rebuild

Use the admitted Stage1 bootstrap artifact to rebuild the selected checker into Stage2. Validate Stage2 independently again.

For the bounded P12 target, recursive convergence criterion is:

```text
Stage1 normalized artifact == Stage2 normalized artifact
AND
Stage1 behavior == source semantics
AND
Stage2 behavior == source semantics
AND
generator identity != validator identity
```

Byte-for-byte equality is preferred because the chosen Bootstrap Core encoding is deterministic; semantic equality remains independently checked and is not inferred from byte equality.

### B6 — narrowed trusted base

P12 may claim trust reduction only to the published B0 seed plus the independent validation assumptions actually recorded in the bootstrap manifests. It must not claim the external Rust seed has disappeared.

### B7 — trusting-trust regression proof

Execute the D1A negative controls including:

```text
validator == generator -> reject
single path alone claims success -> reject
unexpected artifact diff -> reject
seed/provenance mismatch -> reject
normalization masks semantic change -> reject
failed equivalence -> never admit successor
```

## Stage model selected

Bootstrap generation is independent from mathematical universe generation:

```text
U_g = mathematical authority generation
T_g = bootstrap/trust generation
```

Selected progression:

```text
T0 / Stage0
  pinned Rust 1.98 external seed
  -> builds initial Bootstrap Core generator + independent validator

T1 / Stage1
  canonical Formula Bootstrap Core source
  -> generator emits identity-checker successor bytecode
  -> independent validator recompiles + behavior-checks
  -> admitted only after diverse validation

T2 / Stage2
  admitted Stage1 bootstrap path rebuilds the same selected checker
  -> independent validator repeats validation
  -> deterministic convergence required
```

No T-generation transition may alter `U_g` or create mathematical Certification/Promotion authority.

## Bootstrap-equivalence evidence format

P12 should implement the D1A `BootstrapRebuildManifest` with these bindings:

```text
predecessor bootstrap generation
candidate successor generation
generator identity
validator identity
source tree/source program digest
build recipe digest
produced artifact digest(s)
independent artifact digest(s)
normalization rule digest
equivalence criterion
semantic validation evidence
negative-control evidence
seed provenance identity
```

For this P12 target the preferred equivalence criterion is:

```text
NormalizedArtifact + exhaustive bounded semantic equivalence
```

Because the Bootstrap Core encoding is deterministic, successful canonical proof should additionally demonstrate byte-for-byte equality between independently generated candidate and validator artifact.

## Final decision

P12 will **not** attempt to self-host Rust.

It will self-host the smallest authority-critical Formula checker semantics through a Formula-owned deterministic Bootstrap Core, while retaining the Rust toolchain as an explicit hashed B0 seed. A distinct checker-owned reference path validates every successor. Stage1 and Stage2 must converge and independently preserve semantics before bootstrap generation advances.

This strategy directly satisfies the frozen gate:

> a selected authority-critical component is rebuilt by the self-host path and accepted only after an independent path validates the successor.

It also gives P12 a meaningful trusting-trust negative-control surface without pretending the current external compiler has certified itself.
